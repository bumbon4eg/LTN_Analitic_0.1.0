# Установка

Эта инструкция разделяет установку на две части: **Factorio-мод** и текущий **Gateway**. Standalone `gateway.exe` пока не входит в этот снимок проекта, поэтому для Gateway ниже используется запуск из исходников.

---

## 1. Factorio-мод

### Требования

- Factorio 2.0;
- Logistic Train Network `>= 2.0.0`;
- дополнительные optional dependencies устанавливаются только при необходимости и перечислены в `info.json`.

Factorio ожидает `info.json` в корне установленного мода, а `control.lua` является runtime-точкой входа. `thumbnail.png` размещается там же и используется Mod Portal/внутриигровым браузером. Рекомендуемый размер миниатюры — 144×144 px.

[Официальная документация Factorio: структура мода](https://lua-api.factorio.com/latest/auxiliary/mod-structure.html)

### Для обычного пользователя

Если опубликована готовая версия мода, установите её обычным способом через Mod Portal или установите предоставленный пакет мода в каталог `mods`.

После запуска игры убедитесь, что:

1. `Logistic Train Network` установлен и включён;
2. `LTN Analitic` включён;
3. мир загружен без ошибок модов.

### Для разработчика, работающего из исходников

В репозитории исходники Lua находятся в `code/`, поэтому сам корень Git-репозитория не является готовой runtime-папкой мода.

Создайте каталог:

```text
%APPDATA%\Factorio\mods\LTN_Analitic_0.1.1\
```

и скопируйте в него:

```text
info.json
thumbnail.png
code\*.lua
```

В результате Factorio должен видеть такую структуру:

```text
LTN_Analitic_0.1.1/
├── info.json
├── thumbnail.png
├── control.lua
├── actions.lua
├── buffer.lua
├── jsonl.lua
├── storage.lua
├── tools.lua
├── types.lua
├── debug.lua
└── UUID_V4.lua
```

`types.lua` содержит аннотации для редактора и может не участвовать в runtime, но его допустимо хранить рядом с остальными Lua-файлами.

> В проекте намеренно нет скрипта сборки Factorio ZIP. Результат модификации должен содержать только runtime-файлы мода; `gateway`, `schemas` и техническая документация не являются содержимым Factorio-мода.

### Где искать JSONL

Мод записывает данные через `helpers.write_file()` в каталог `script-output`. На Windows по умолчанию пользовательские данные Factorio находятся в `%APPDATA%\Factorio`, поэтому файл проекта ожидается здесь:

```text
%APPDATA%\Factorio\script-output\LTN_Analitic\data.jsonl
```

[Factorio Wiki: пользовательский каталог данных](https://wiki.factorio.com/User_data_directory)

Фактический путь может отличаться, если пользователь изменил каталог записи Factorio.

## 2. PostgreSQL

Gateway текущей версии подключается непосредственно к PostgreSQL.

Для работы потребуется:

- имя сервера или IP;
- порт PostgreSQL, обычно `5432`;
- имя базы данных;
- пользователь;
- пароль;
- при необходимости SSL/TLS.

Рекомендуется выделить отдельную базу и отдельного пользователя Gateway. Подробности и пример SQL — [docs/database.md](database.md).

## 3. Установка текущего Gateway из исходников

### Шаг 1. Установите Python

Для текущего проекта рекомендуется Python 3.12.

Проверьте:

```powershell
py --version
```

или:

```powershell
python --version
```

### Шаг 2. Создайте виртуальное окружение

Из корня репозитория:

```powershell
Set-Location .\gateway
py -3.12 -m venv .venv
```

### Шаг 3. Активируйте окружение

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов, см. [docs/troubleshooting.md](troubleshooting.md).

### Шаг 4. Установите зависимости

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Шаг 5. Запустите Gateway

```powershell
python main.py
```

## 4. Первый запуск Gateway

При отсутствии локальной конфигурации Gateway открывает мастер первичной настройки.

### Шаг 1 — Источник данных

Укажите JSONL-файл.

Обычно это:

```text
%APPDATA%\Factorio\script-output\LTN_Analitic\data.jsonl
```

Можно выбрать другой файл через кнопку **«Обзор…»**.

### Шаг 2 — Назначение

В текущей реализации доступен один вариант:

```text
PostgreSQL
```

### Шаг 3 — Подключение

Заполните:

```text
Сервер
Порт
Имя базы
Пользователь
Пароль
SSL/TLS
```

Если SSL/TLS включён, Gateway использует проверку сертификата и имени сервера. Для частного CA не отключайте проверку ради обхода ошибки; установите необходимый доверенный CA в систему или настройте сервер соответствующим образом.

### Шаг 4 — Проверка и сохранение

Нажмите **«Проверить и сохранить»**.

Gateway выполняет тестовый запрос к PostgreSQL. При успешном подключении настройки записываются в пользовательский профиль, после чего открывается рабочая панель.

---

## 5. Запуск после первичной настройки

Повторно выполните:

```powershell
Set-Location .\gateway
.\.venv\Scripts\Activate.ps1
python main.py
```

Откроется рабочее окно Gateway.

Доступные действия:

- **Настройки** — изменить путь к JSONL и параметры БД;
- **Проверить подключение** — повторно проверить PostgreSQL;
- **Запустить импорт** — прочитать выбранный JSONL и загрузить данные.

---

## 6. Порядок запуска всей системы

Для первой проверки используйте такой порядок:

```text
1. Запустить Factorio
2. Загрузить мир с LTN Analitic + LTN
3. Дождаться появления data.jsonl
4. Убедиться, что JSONL содержит записи
5. Подготовить PostgreSQL
6. Запустить Gateway
7. Настроить путь к JSONL и PostgreSQL
8. Проверить соединение
9. Нажать «Запустить импорт»
10. Проверить orders / order_events в БД
```

Для быстрой проверки JSONL внутри Factorio можно использовать:

```text
/ltn_write_jsonl
```

---

## 7. Удаление / сброс настроек Gateway

Текущая конфигурация хранится в:

```text
%APPDATA%\LTN_Analitics_gateway\config.conf
```

Чтобы заставить Gateway снова открыть мастер первичной настройки, остановите программу и удалите этот файл.

> Удаление `config.conf` сбросит только настройки Gateway и локальную статистику. JSONL-файл и база данных от этого не удаляются.

---

## 8. Standalone gateway.exe

Пользовательская финальная схема проекта будет отличаться от текущей разработки:

```text
Factorio мод
    ↓
JSONL
    ↓
gateway.exe
    ↓
PostgreSQL / API
```

В этой версии Python и зависимости не потребуются пользователю. Для первого запуска будет сохранён тот же концепт мастера настройки, а конфиденциальные данные будут храниться вне мода.

Отдельная инструкция для release-версии появится после завершения упаковки и тестирования `gateway.exe`.
