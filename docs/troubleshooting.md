# Устранение проблем

## Мод не появляется в Factorio

Проверьте структуру установленного мода:

```text
LTN_Analitic_0.1.1/
├── info.json
├── control.lua
├── actions.lua
├── buffer.lua
├── jsonl.lua
├── storage.lua
├── tools.lua
├── debug.lua
└── UUID_V4.lua
```

`control.lua` и остальные Lua-файлы не должны оставаться внутри `code/` уже установленного runtime-каталога.

Также проверьте, что установлен Logistic Train Network и игра соответствует `factorio_version` мода.

[Factorio: структура мода](https://lua-api.factorio.com/latest/auxiliary/mod-structure.html)

---

## `data.jsonl` не создаётся

Проверьте:

1. мод включён;
2. мир действительно загружен;
3. `control.lua` успешно выполнился;
4. LTN установлен;
5. путь пользовательских данных Factorio не был изменён.

Для немедленного теста используйте в игре:

```text
/ltn_write_jsonl
```

По умолчанию файл ожидается здесь:

```text
%APPDATA%\Factorio\script-output\LTN_Analitic\data.jsonl
```

---

## Gateway сообщает «Файл данных не найден»

Откройте:

```text
%APPDATA%\Factorio\script-output\LTN_Analitic\
```

и убедитесь, что там есть:

```text
data.jsonl
```

Если файл находится в другом месте, используйте **Настройки → Обзор…** и укажите фактический путь.

---

## Gateway не подключается к PostgreSQL

Проверьте по порядку:

1. доступен ли сервер;
2. правильный ли host;
3. правильный ли port;
4. существует ли база;
5. правильны ли пользователь и пароль;
6. разрешены ли подключения с компьютера пользователя;
7. не блокирует ли соединение firewall;
8. соответствует ли режим SSL настройке сервера.

До проверки Gateway можно выполнить:

```powershell
Test-NetConnection <HOST> -Port 5432
```

## Ошибка SSL-сертификата

Если SSL включён, Gateway проверяет сертификат сервера.

Типичная причина — сервер использует сертификат от собственного CA, которому Windows/Python не доверяет.

Правильный путь — установить цепочку доверия или использовать корректный сертификат. Не отключайте проверку сертификата только для обхода ошибки.

---

## Gateway не запускается после установки зависимостей

Проверьте, что активировано правильное виртуальное окружение:

```powershell
Get-Command python
python --version
```

Путь должен указывать на:

```text
gateway\.venv\Scripts\python.exe
```

При необходимости пересоздайте окружение:

```powershell
Remove-Item .\.venv -Recurse -Force
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

---

## PowerShell запрещает `Activate.ps1`

Если выводится ошибка Execution Policy, можно разрешить запуск локальных скриптов для текущего пользователя. Например, из PowerShell пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

После этого:

```powershell
.\.venv\Scripts\Activate.ps1
```

Изменять системную политику для всей машины для этой задачи не требуется.

---

## Повторный импорт показывает 0 новых записей

Это может быть нормальным поведением.

Gateway использует уникальные идентификаторы orders/events и пропускает записи, которые уже присутствуют в БД.

При этом текущая версия перечитывает весь JSONL каждый раз. Это безопаснее для повторного запуска, но не является оптимальным incremental ingestion.

---

## JSONL повреждён

Если в одном из пакетов содержится некорректный JSON, Gateway сообщает номер строки.

Проверьте эту строку отдельно и убедитесь, что Factorio не был принудительно остановлен в момент записи файла.

Для отладки можно сначала скопировать JSONL, не изменяя оригинал, и работать с копией.

---

## После обновления мода старый save ведёт себя неправильно

Проверьте:

- `storage.ensure()`;
- `script.on_configuration_changed`;
- миграцию старых storage-полей;
- изменение `world_id`;
- изменение `protocol_version`.

Для таких проблем нужен прежде всего `factorio-current.log` и конкретный save, на котором воспроизводится ошибка.
