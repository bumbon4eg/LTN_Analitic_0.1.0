# Архитектура LTN Analytic

## Назначение

Проект состоит из двух взаимодействующих частей:

1. **Factorio-мод** хранится исходниками в `code/`, собирает данные Logistic
   Train Network и записывает их в JSON Lines.
2. **`gateway/`** — отдельное приложение, которое читает JSONL и загружает
   данные в базу данных. На текущем этапе его реализация не описывается
   подробно и не изменяется в рамках организации проекта.

Такое разделение позволяет менять способ хранения данных, не встраивая
подключение к базе данных в Factorio-мод.

Мод предназначен для продвинутых пользователей, исследующих игру и работу LTN.
Он не предоставляет полноценный интерфейс аналитики внутри Factorio. Для полной
работы требуется собственная база данных и отдельный `gateway`, который читает
JSONL-файл из `script-output/LTN_Analitic/` и загружает данные в БД.

Перед установкой и использованием следует прочитать [README.md](../README.md)
и [gateway/README.md](../gateway/README.md). `info.json` содержит краткое
описание для Factorio, а подробная инструкция поставляется вместе с проектом.

## Структура репозитория

```text
.
├── code/                    # Исходный Lua-код Factorio-мода
│   ├── control.lua          # Точка входа после сборки
│   ├── actions.lua          # Обработка событий LTN
│   ├── buffer.lua           # Накопление данных
│   ├── jsonl.lua            # Формирование JSONL-пакетов
│   ├── storage.lua          # Persistent state Factorio
│   ├── debug.lua            # Команды диагностики
│   ├── tools.lua            # Чтение данных из Factorio API
│   ├── types.lua            # LuaLS-аннотации
│   └── UUID_V4.lua           # UUID игрового мира
├── build.ps1                # Сборка Factorio-архива
├── info.json                # Метаданные и зависимости Factorio-мода
├── schemas/                 # JSON Schema внешнего контракта данных
├── gateway/                 # Отдельный загрузчик JSONL в БД
├── docs/                    # Документация проекта
└── .dev/                    # Локальные материалы разработки
```

Исходный Lua-код находится в `code/`. Скрипт `build.ps1` копирует `info.json`
и Lua-файлы из `code/` в структуру Factorio-мода и создаёт ZIP в `dist/`.

## Поток данных

```text
LTN event
   -> code/actions.lua
   -> code/buffer.lua
   -> code/jsonl.lua (каждые 360 тиков)
    -> script-output/LTN_Analitic/data.jsonl
    -> gateway
    -> database
```

### Сбор данных

`code/control.lua` регистрирует обработчики жизненного цикла Factorio, обработчики
событий LTN, периодическую запись JSONL и команды диагностики.

`code/actions.lua` реагирует на события LTN, поддерживает активные доставки и
формирует данные заказов и событий заказов. Данные поездов и станций получают
через `tools.lua`.

`code/buffer.lua` накапливает четыре категории данных:

- `active_orders`;
- `order_events`;
- `trains`;
- `stations`.

Состояние сохраняется в глобальном Factorio `storage` через `storage.lua`.
Перед записью `jsonl.lua` собирает snapshot буфера, сериализует его через
Factorio JSON API и очищает буфер после успешной записи.

### Формат экспорта

Файл `script-output/LTN_Analitic/data.jsonl` содержит один JSON-документ
на строку. Пакет включает:

- `protocol_version` — версию протокола;
- `world_id` — постоянный UUID игрового мира;
- `sequence_number` — возрастающий номер пакета в рамках мира;
- `tick` — игровой тик создания snapshot;
- `active_orders` — активные заказы;
- `order_events` — события жизненного цикла заказов;
- `trains` — данные поездов;
- `stations` — данные станций.

Каноническое описание пакета находится в
[schemas/packet.schema.json](../schemas/packet.schema.json). Остальные файлы
в `schemas/` описывают вложенные структуры и события протокола.

Потребитель должен обрабатывать файл построчно, валидировать пакет по схеме,
использовать `world_id` для разделения игровых миров и `sequence_number` для
контроля порядка, повторов и пропусков.

## Версионирование протокола

`protocol_version` — версия формата JSONL между модом и `gateway`; она не равна
версии Factorio-мода из `info.json`.

- необязательное обратно совместимое поле может сохранять текущую версию;
- переименование, изменение типа, обязательности или смысла поля требует новой
   major-версии протокола;
- при изменении обновляются `code/jsonl.lua`, схемы, модели и трансформации
   `gateway`, README и этот документ;
- `gateway` должен отклонять или помещать в quarantine неизвестные версии;
- `world_id` разделяет миры, а `sequence_number` выявляет пропуски и повторы.

Инструкция для `gateway` находится в [gateway/README.md](../gateway/README.md).

## Жизненный цикл мода

- `script.on_init` — инициализирует persistent state и регистрирует обработчики.
- `script.on_configuration_changed` — повторяет регистрацию после изменения
  конфигурации или версии мода.
- `script.on_load` — повторно регистрирует обработчики после загрузки сохранения.

Экспорт JSONL регистрируется через `script.on_nth_tick(360, jsonl.write)`.
Период равен 360 игровым тикам, то есть 6 секундам при стандартной скорости.

## Диагностика

| Команда | Назначение |
| --- | --- |
| `/ltn_debug_world_id` | Показать идентификатор мира |
| `/ltn_regenerate_world_id` | Принудительно создать новый идентификатор мира |
| `/ltn_debug_orders` | Показать активные доставки |
| `/ltn_clear_active` | Очистить активные доставки |
| `/ltn_debug_buffer` | Показать содержимое буфера |
| `/ltn_debug_send_data` | Показать подготовленный snapshot |
| `/ltn_clear_buffer` | Очистить буфер отправки |
| `/ltn_debug_order <id>` | Показать заказ и его события |
| `/ltn_write_jsonl` | Немедленно записать текущий буфер в JSONL |

Принудительная смена `world_id` начинает новую логическую серию данных, поэтому
команду следует использовать только намеренно или при восстановлении состояния.

## Правила изменения контракта

`schemas/` — общий контракт между Factorio-модом и `gateway`. При изменении
структуры JSON-пакета нужно одновременно:

1. обновить Lua-код формирования пакета;
2. обновить соответствующие JSON Schema;
3. обновить описание формата в этом документе;
4. проверить совместимость загрузчика `gateway` отдельным изменением.

Изменения в `gateway/` должны проверяться отдельно от Factorio-мода.
